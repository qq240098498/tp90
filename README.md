# tp90 检查规则与命中清单工作台

一个本地小工具：把团队约定要检查的写法整理成规则，规则再归进若干规则集、按目录前缀分管各片目录；把需要检查的文件内容收进来，点一下扫一遍，命中的地方会记到具体的文件与行上。规则编码写得不合规矩、同一条规则编码重复使用、文件路径重复收录、内容为空，保存时当场就会指出来；规则集之间的范围撞上了，页面上会列清是哪几条、重叠在哪一段，并给出主次关系。

数据全部存在本机的数据文件里，不连数据库，也不调用任何外部服务。

## 技术栈

- 后端：Node.js（>=18）与 Express，前后端同一个进程
- 前端：原生 HTML、CSS 与 JavaScript，页面文件由后端静态目录直接提供，没有构建步骤
- 存储：本地 JSON 文件 `data/db.json`

## 项目结构

```
tp90/
├── server/
│   ├── index.js        # 服务入口、静态目录、接口路由

│   ├── sets.js         # 规则集的校验、新增、修改、查询与删除

│   ├── errors.js       # 带错误码与出错位置的业务异常
│   └── store.js        # 数据读写：载入、整理结构与落盘
├── public/
│   ├── index.html      # 主界面：规则区、规则集区、文件区、目录生效与冲突区、命中清单区
│   ├── app.js          # 页面交互逻辑
│   └── style.css       # 页面样式
├── data/
│   └── db.json         # 本地数据文件（含十三条规则、十二个文件与四个规则集）
├── package.json
├── .gitignore
└── README.md
```

## 启动方式

```bash
npm install
npm start
```

启动后打开页面地址：<http://localhost:5090>

端口固定为 `5090`，如需临时改动可在启动前设置环境变量 `PORT`。

## 页面怎么用

1. 规则区列出编码、名称、级别、状态、适用文件类型、所在规则集与匹配写法，可以按级别、状态、适用文件类型筛选，也能按编码、名称或匹配写法搜索；支持新建、编辑与删除。删除规则时它会同时从所有规则集里摘掉
2. 规则集区列出编码、名称、目录前缀、成员规则与说明，可以按编码、名称或目录前缀搜索；新建与编辑时目录前缀每行写一个，成员规则从现有规则里勾，一条规则可以进多个集子
3. 文件区列出收录进来的文件路径、类型、行数与更新时间，点看内容可以把整份内容展开在下面；点编辑会把路径、内容与备注回填到表单，支持收录新文件与移出清单
4. 目录生效一览按收录文件的路径归出目录，逐个目录列出管得到它的规则、每条来自哪个规则集；没被任何规则集覆盖到的目录、不在任何规则集里的规则都单独列出来
5. 范围冲突判断把规则集之间撞上的情形分三类列清：同一条规则落在多个规则集且目录范围重叠、同一目录下两条规则的匹配写法指向同一段文字但级别不同、一个规则集的目录范围把另一个整个包住；每条都写清是谁、重叠在哪一段、谁主谁次
6. 命中清单区顶部可以选定只看某一条规则、某一个文件或者某一个级别，点按规则扫一遍，页面上给出这一轮参与比对的规则条数、范围里的文件个数、一共命中多少条，并按级别、按规则、按文件分别汇总
7. 任何一步不成立时，页面顶部给出说明，并尽量把问题标到对应的输入项上

## 比对口径

- 只有状态为启用的规则参与比对，停用的规则不会产生命中；如果指定了一条停用的规则，页面上会写明这一轮它没有参与
- 适用文件类型写成全部的规则管所有文件，写成某一种类型的只比对该类型的文件，类型按路径后缀判断（支持 js、sh、md、yml）
- 一条规则命中与否看文件里有没有出现它登记的匹配写法，区分大小写，命中的是包含这个写法的整行
- 命中按规则编码、文件路径、行号排序，同一行同时踩到多条规则时逐条各记一条

## 范围与冲突口径

- 目录按收录文件的路径归出来，去掉最后一段文件名；规则集登记的目录前缀盖住与它相等或在它更深层的所有目录
- 一个目录下生效的规则，是所有盖住它的规则集的成员取并集，同一条规则只算一次，并标明来自哪些规则集；没被任何规则集盖住的目录单独列出
- 冲突一：同一条规则落在两个规则集里，且两个集子的目录范围有重叠。重叠取两边前缀相交的那一段；这段上以目录更具体的规则集为主，一样具体时编码靠前的为主
- 冲突二：同一个目录下两条规则的匹配写法一个含住另一个（或完全一样），但级别不同，且适用文件类型搭得上。共同指向的那段文字取较长的那个写法；以级别高的规则为主
- 冲突三：一个规则集的目录范围把另一个整个包住（对方的每个前缀都落在自己的某个前缀下）。被包住的集子目录更具体，在自己的范围内为主；两边范围完全相同时编码靠前的为主

## 登记口径

- 规则编码写成大写字母加短横线加数字，例如 `CODE-001`，最长 20 个字符，且不能重复
- 级别只有三种：提示、警告、错误
- 状态只有两种：启用、停用
- 匹配写法不能为空，最长 60 个字符
- 文件路径最长 120 个字符，只用字母数字、点、下划线、短横线与斜线，后缀必须是收录范围内的几种，且不能重复
- 文件内容不能为空，最长 4000 个字符
- 规则集编码与规则编码同一种写法，例如 `SET-001`，最长 20 个字符，且在规则集之间不能重复
- 规则集名称必填，最长 40 个字符
- 目录前缀至少写一个、最多 20 个，每个最长 120 个字符，只用字母数字、点、下划线、短横线与斜线，不能用相对上级的写法；重复的前缀只留一个
- 成员规则必须从现有规则里挑，可以一个都不挑；删除规则时会自动从所有规则集里摘掉

## 数据存储

所有数据写在 `data/db.json`，结构为 `{ "rules": [...], "files": [...], "ruleSets": [...] }`。落盘时先把内容写进同名临时文件，再用改名的方式替换正式文件，写入过程中断也不会把数据文件写坏；文件缺失或内容损坏时会自动回落到初始数据。

## 接口一览

| 方法   | 路径                 | 说明                                             |
| ------ | -------------------- | ------------------------------------------------ |
| 方法   | 路径                | 说明                                             |
| ------ | ------------------- | ------------------------------------------------ |
| GET    | /api/health         | 服务状态检查                                     |
| GET    | /api/rules          | 规则清单（一并带出所在规则集），支持按级别、状态、适用文件类型筛选与关键词搜索 |
| POST   | /api/rules          | 新建规则                                         |
| GET    | /api/rules/:id      | 查看单条规则                                     |
| PATCH  | /api/rules/:id      | 修改规则                                         |
| DELETE | /api/rules/:id      | 删除规则（同时从所有规则集里摘掉）               |
| GET    | /api/rule-sets      | 规则集清单（成员规则一并带出），支持关键词搜索   |
| POST   | /api/rule-sets      | 新建规则集                                       |
| GET    | /api/rule-sets/:id  | 查看单个规则集                                   |
| PATCH  | /api/rule-sets/:id  | 修改规则集                                       |
| DELETE | /api/rule-sets/:id  | 删除规则集（规则本身保留）                       |
| GET    | /api/files          | 文件清单，支持按类型筛选与关键词搜索             |
| POST   | /api/files          | 收录文件                                         |
| GET    | /api/files/:id      | 查看单个文件（含完整内容）                       |
| PATCH  | /api/files/:id      | 修改文件                                         |
| DELETE | /api/files/:id      | 把文件移出清单                                   |
| GET    | /api/scope          | 按目录算出生效规则、未覆盖目录、未归组规则与三类范围冲突 |
| POST   | /api/scan           | 按启用的规则扫一遍，返回命中清单与汇总           |

接口出错时统一返回 `{ "error": { "code": "...", "message": "...", "field": "..." } }`，其中 `field` 用于让页面把问题标到具体的输入项上。
