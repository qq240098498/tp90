# tp90 检查规则与命中清单工作台

一个本地小工具：把团队约定要检查的写法整理成规则，规则再归进若干规则集、每个规则集写清管哪些目录前缀；把需要检查的文件内容收进来，点一下扫一遍，命中的地方会记到具体的文件与行上。页面按目录把生效的规则算出来，规则集的范围撞上时给出主次判断。规则编码写得不合规矩、同一条规则编码重复使用、规则集名称重复、前缀互相包住、文件路径重复收录、内容为空，保存时当场就会指出来。

数据全部存在本机的数据文件里，不连数据库，也不调用任何外部服务。

## 技术栈

- 后端：Node.js（>=18）与 Express，前后端同一个进程
- 前端：原生 HTML、CSS 与 JavaScript，页面文件由后端静态目录直接提供，没有构建步骤
- 存储：本地 JSON 文件 `data/db.json`

## 项目结构

```
tp90/
├── server/
│   ├── index.js        # 服务入口、静态目录、接口路由
│   ├── api.js          # 规则、规则集、文件、生效范围与扫描的对外动作
│   ├── rules.js        # 规则的校验、新增、修改、查询与删除
│   ├── rulesets.js     # 规则集的校验、新增、修改、查询与删除
│   ├── coverage.js     # 按目录算生效规则，并给出范围冲突的主次判断
│   ├── files.js        # 文件内容的校验、收录、修改、查询与删除
│   ├── scan.js         # 按启用规则比对文件并给出命中
│   ├── errors.js       # 带错误码与出错位置的业务异常
│   └── store.js        # 数据读写：载入、整理结构与落盘
├── public/
│   ├── index.html      # 主界面：规则区、规则集区、生效范围区、冲突区、文件区与命中清单区
│   ├── app.js          # 页面交互逻辑
│   └── style.css       # 页面样式
├── data/
│   └── db.json         # 本地数据文件（含十三条规则、四个规则集与十二个文件）
├── package.json
├── .gitignore
└── README.md
```

## 启动方式

```bash
npm install
npm start
```

启动后打开页面地址：<http://localhost:5090>

端口固定为 `5090`，如需临时改动可在启动前设置环境变量 `PORT`。

## 页面怎么用

1. 规则区列出编码、名称、级别、状态、适用文件类型、所属规则集与匹配写法，可以按级别、状态、适用文件类型筛选，也能按编码、名称或匹配写法搜索；支持新建、编辑与删除
2. 规则集区列出名称、目录前缀、成员规则与说明，支持新建、编辑与删除；新建时按行填写目录前缀、勾选归进这个集的规则
3. 按目录生效的规则区把清单里每个目录被哪些规则集覆盖、生效的是哪几条规则、每条来自哪个规则集都列出来；没有被任何规则集覆盖的目录单独列在下面，没归进任何规则集的规则也会点名
4. 范围冲突与主次区分三类列出范围撞上的地方：是哪几条、重叠在哪一段、以谁为主，没有冲突的类别会写明
5. 文件区列出收录进来的文件路径、类型、行数与更新时间，点看内容可以把整份内容展开在下面；点编辑会把路径、内容与备注回填到表单，支持收录新文件与移出清单
6. 命中清单区顶部可以选定只看某一条规则、某一个文件或者某一个级别，点按规则扫一遍，页面上给出这一轮参与比对的规则条数、范围里的文件个数、一共命中多少条，并按级别、按规则、按文件分别汇总
7. 任何一步不成立时，页面顶部给出说明，并尽量把问题标到对应的输入项上

## 范围与冲突口径

- 目录前缀命中：目录等于前缀，或者落在前缀的下一层之下（前缀 `src` 管得到 `src/server`，管不到 `scripts`）
- 一个目录的生效规则：覆盖这个目录的规则集里的成员规则；规则的适用文件类型管不到目录里任何一类文件时，不算这个目录的生效规则
- 同一条规则落在两个规则集里、且两个集的目录范围有重叠：列出重叠在哪一段；每一段以更具体（更长）的前缀所在的规则集为主，两个集的前缀相同则以先建立的规则集为主
- 同一个目录下两条启用规则的写法指向同一段文字（一条写法包含另一条，或完全相同）、但级别不同：列出是哪两条、共同指向哪段文字、在哪些目录同时生效；以级别更高的规则为主，另一条在这些目录降为参考；停用的规则不参与这类判断
- 一个规则集的目录范围把另一个规则集整个包住：列出谁包住谁、被包住的是哪几段；被包住的集在比自己更具体的段上为主，前缀相同则按建立先后定主，其余目录归范围宽的集；两个集范围完全相同时以先建立的为主

## 比对口径

- 只有状态为启用的规则参与比对，停用的规则不会产生命中；如果指定了一条停用的规则，页面上会写明这一轮它没有参与
- 适用文件类型写成全部的规则管所有文件，写成某一种类型的只比对该类型的文件，类型按路径后缀判断（支持 js、sh、md、yml）
- 一条规则命中与否看文件里有没有出现它登记的匹配写法，区分大小写，命中的是包含这个写法的整行
- 命中按规则编码、文件路径、行号排序，同一行同时踩到多条规则时逐条各记一条

## 登记口径

- 规则编码写成大写字母加短横线加数字，例如 `CODE-001`，最长 20 个字符，且不能重复
- 级别只有三种：提示、警告、错误
- 状态只有两种：启用、停用
- 匹配写法不能为空，最长 60 个字符
- 规则集名称不能为空，最长 40 个字符，且不能重复
- 规则集的目录前缀至少一个、最多 20 个，每个最长 120 个字符，只用字母数字、点、下划线、短横线与斜线，不能用相对上级的写法；同一个集里一个前缀把另一个整个包住时只留一个
- 规则集的成员规则必须是清单里还真在的规则；删除规则时会一并从各个规则集里摘掉，删除规则集不影响规则本身
- 文件路径最长 120 个字符，只用字母数字、点、下划线、短横线与斜线，后缀必须是收录范围内的几种，且不能重复
- 文件内容不能为空，最长 4000 个字符

## 数据存储

所有数据写在 `data/db.json`，结构为 `{ "rules": [...], "ruleSets": [...], "files": [...] }`。落盘时先把内容写进同名临时文件，再用改名的方式替换正式文件，写入过程中断也不会把数据文件写坏；文件缺失或内容损坏时会自动回落到初始数据。

## 接口一览

| 方法   | 路径                 | 说明                                             |
| ------ | -------------------- | ------------------------------------------------ |
| GET    | /api/health          | 服务状态检查                                     |
| GET    | /api/rules           | 规则清单，支持按级别、状态、适用文件类型筛选与关键词搜索 |
| POST   | /api/rules           | 新建规则                                         |
| GET    | /api/rules/:id       | 查看单条规则                                     |
| PATCH  | /api/rules/:id       | 修改规则                                         |
| DELETE | /api/rules/:id       | 删除规则（一并从规则集里摘掉）                   |
| GET    | /api/rule-sets       | 规则集清单（含成员规则的具体信息）               |
| POST   | /api/rule-sets       | 新建规则集                                       |
| GET    | /api/rule-sets/:id   | 查看单个规则集                                   |
| PATCH  | /api/rule-sets/:id   | 修改规则集                                       |
| DELETE | /api/rule-sets/:id   | 删除规则集（规则本身保留）                       |
| GET    | /api/coverage        | 按目录的生效规则、未覆盖目录、未归组规则与三类范围冲突 |
| GET    | /api/files           | 文件清单，支持按类型筛选与关键词搜索             |
| POST   | /api/files           | 收录文件                                         |
| GET    | /api/files/:id       | 查看单个文件（含完整内容）                       |
| PATCH  | /api/files/:id       | 修改文件                                         |
| DELETE | /api/files/:id       | 把文件移出清单                                   |
| POST   | /api/scan            | 按启用的规则扫一遍，返回命中清单与汇总           |

接口出错时统一返回 `{ "error": { "code": "...", "message": "...", "field": "..." } }`，其中 `field` 用于让页面把问题标到具体的输入项上。
